Updating a container means replacing its image, which cannot be done from inside it. Run this on the Docker host: 
cd /opt/risksentinel/app          # the git clone
git pull
docker build -t risksentinel:latest .
docker stop risk-sentinel && docker rm risk-sentinel
docker run -d --name risk-sentinel --restart unless-stopped \
  -p 8080:8080 \
  -v vuln-portal_vuln_data:/app/instance \
  -v vuln-portal_vuln_uploads:/app/uploads \
  -e SECRET_KEY="$SECRET_KEY" \
  risksentinel:latest
Keep the volume names exactly as they are. They hold the database and uploads, and a different name silently creates an empty volume rather than failing.

To make this page work instead, mount the checkout over the application directory by adding -v /opt/risksentinel/app:/app to the run command. The container then runs the git working tree directly, and updating becomes pull and restart with no rebuild, unless requirements.txt changes.
